## 1. 제작한 것 소개

**차곡차곡 2.0**은 교재·문제집·강의의 진도와 회독을 기록하고, 시험 일정과 실제 학습 이력을 바탕으로 **오늘의 권장 학습량, 복습할 범위, 예상 완료일**을 보여 주는 반응형 학습 관리 웹앱입니다. 대학생과 자격증·공무원 시험 준비생처럼 여러 자료와 시험을 병행하는 사용자를 대상으로 합니다.

기존 1.0의 **자료 등록, 진도 기록, 회독, 부분 복습, 메모, 로컬 백업**은 유지하고, 시험·자동 계획·이해도별 복습·통계·식물 성장·PC/모바일 UI로 기능을 확장했습니다. 데이터는 사용자 브라우저에 저장되며 별도 로그인 기능은 없습니다.

### 핵심 기능

- **학습 자료 관리:** 자료 등록·수정·삭제, 유형별 단위, 진도·회독·부분 복습 기록, 메모, 목표 완료일, 일시 중단·완료·보관·복원
- **시험 관리:** 시험 등록·수정, 선택적 시험일 및 D-Day, 한 자료의 여러 시험 연결, 단일 우선 시험, 쉬는 날짜·요일, 시험 중단·재개·재응시
- **학습 계획:** 실제 남은 분량과 학습 가능일을 이용한 자동 권장량, 사용자 지정 일일 분량, 계획상 예상 완료일·실제 속도 예상일·목표일의 구분
- **이해도 기반 복습:** 쉬움/보통/어려움, 1·3·7일 기본 간격, 이후 간격 조정, 밀린 복습·시험 전 집중 복습·중복 추천 통합
- **학습 통계:** 주·월·최근 3/6개월 통계, 학습 캘린더와 날짜별 기록, 현재 회독 학습 속도
- **시각화·테스트:** 자료별 5단계 성장 픽셀 식물, 설정의 독립 ON/OFF 가상 데이터 시연 모드

### 개발·실행 환경

- **개발:** HTML, CSS, JavaScript (별도 프레임워크 없음)
- **저장:** 브라우저 LocalStorage 기반, 가상 테스트 데이터는 실사용 저장소와 분리
- **배포 구성:** GitHub Pages 정적 호스팅 및 PWA 관련 파일 (`manifest.webmanifest`, `service-worker.js`)
- **로컬 실행:** 프로젝트 루트에서 `python -m http.server 8000` 실행 후 `http://localhost:8000` 접속
- **배포 캐시 갱신:** 관련 소스·에셋 변경 후 `node scripts/build-pwa.cjs` 실행 (Node.js 설치 필요)

> 실제 배포 URL·Public 설정, 최신 iPhone Safari/홈 화면 설치 PWA, 사용자 실데이터 전환은 이 ZIP만으로 최종 완료를 확인할 수 없어 제출 전 직접 확인해야 합니다.

- **사용 방식:** 프로젝트 `AGENTS.md`에서 스킬 경로를 안내하고, 해당 작업에서 `skills/chagok-data-guard/SKILL.md`의 규칙에 따라 데이터 경계·검증 범위를 확인
- **적용 사례:** 저장·기록 보호 점검(CG-SKILL-013), 자료·복습 연결 단계의 원본/파생 데이터 분리 확인, 1.0 소스 대조 및 제출 표현 검토(CG-SKILL-062)

# 차곡차곡 데이터·기록 보호

이 파일은 2026-10-24 새로 작성한 프로젝트용 버전이다. 과거 CG-SKILL-001~012에서 사용했다는 원문을 복원한 파일이 아니다.

## 작업 범위 결정

프로젝트 루트의 최신 사용자 지시, `PROGRESS.md`, `docs/TODO.md`에서 이번 작업 범위와 번호를 확인한다. 관련 요구사항만 `docs/PRD.md`, `docs/PRD-updates.md`에서 읽는다. 후속 결정이 초기 기획보다 우선한다. 스킬 준비·보고서 정리는 다음 앱 구현 단계의 승인이 아니다. Git 커밋은 사용자가 직접 담당한다는 현재 지시를 따른다.

현재 상태를 고정된 전제로 재사용하지 말고 소스를 확인한다. 조사 시작점은 `dist/app.js`의 예시 자료와 폼 submit 처리, `dist/exam-management.js`의 KEY/load/save/upgrade, `reference/v1/app.js`의 저장·백업 코드다. 실제 브라우저 저장값을 읽어야 하는 작업인지, 소스나 합성 데이터만으로 가능한지 구분한다.

## 데이터 변경 시 지켜야 할 조건

- `reference/v1` 원본 소스를 변경하지 않는다. 마이그레이션은 사용자 데이터 복사본 또는 합성 데이터로 검증하고 기존 저장값을 성공 확인 전에 덮어쓰지 않는다.
- 자료 ID, 원본 기록 ID·날짜·시각·순서·단위·범위·이해도·회독 이력과 알 수 없는 기존 필드의 보존 방침을 정한다. 파생 상태를 계산하려고 원본 평가를 수정하지 않는다.
- 부분 복습은 전체 진도·회독을 바꾸지 않는다. 다음 회독을 시작해도 과거 회독 기록을 지우지 않는다. 수동 계획·복습일·메모를 자동 추천으로 덮어쓰지 않는다.
- 직접 중단 상태가 자동 중단보다 우선한다. 다중 시험 연결에서는 다른 활성 시험과 시험별 계속 학습 선택을 고려한다. 재개는 해당 시험의 자동 중단 영향만 해제한다.
- 일반·시험 전 복습이 같은 날짜와 범위에서 겹칠 때 추천 표시와 실제 기록을 구분해 이력 중복 생성을 방지한다.
- 미확정 복습 간격·초기 속도·여유일은 `PRD-updates.md`에 따른 사례 확인 전 확정값으로 구현하지 않는다. 고정 D-7/D-14 규칙으로 대체하지 않는다.

2. 수정 전후 `scripts/inspect-boundary.ps1` 결과를 비교한다. 이 도구는 소스 해시와 직접적인 저장 호출 위치만 수집한다. 키 격리와 무손실은 반드시 호출 경로와 실행 결과로 별도 판단한다.
3. 변경 범위에 맞는 사례를 선택한다. 저장 변경은 재로드·왕복·깨진 JSON·미지원 버전·쓰기 실패, 기록 계산은 범위 겹침·동일 날짜 순서·수정/삭제·회독 경계, 시험 상태는 다중 연결·직접 중단·재개·매번 미선택 기본값을 확인한다. 전체 항목을 모든 작업에서 실행할 필요는 없다.
4. 기존 자동 테스트 명령은 `node --test tests/streak.test.cjs tests/exam-management.test.cjs`다. 실행 도구가 없으면 미실행 사유를 남기고 통과 수를 재사용하지 않는다. 브라우저 UI 변경은 관련 흐름과 모바일/PC를 확인하며 Chrome 너비 모의 검증을 실제 Safari/PWA 검증으로 표시하지 않는다.
5. 예시 화면, 시험 미리보기 저장, 실제 학습 데이터 저장을 구분해 TODO·README·PROGRESS의 완료 표현을 검토한다. 파일 해시 동일은 사용자 데이터 전환 성공 증거가 아니다.

## 실제 사용 기록

작업 후 `docs/skill-usage-log.md`와 `.jsonl`에 동일한 고유 ID로 다음 필드를 기록한다.

`id`, `date`(시간을 확인하지 못하면 날짜만), `skill`, `skill_source`, `task`, `todo_refs`, `actions`, `evidence`, `result`, `outcome`, `limitations`.

## 5. 느낀 점과 결론

### 느낀 점 — 제출자 최종 작성 필요

> 아래는 **수정 가능한 초안**이며 실제 본인의 경험으로 확인·수정한 뒤 제출해 주세요.

기존 앱에 새로운 기능을 덧붙이는 과정에서 단순히 기능을 많이 만드는 것보다 **기존 기록을 보존하면서 기능들이 자연스럽게 연결되도록 하는 일**이 중요하다는 점을 알게 되었다. 특히 시험 관리, 학습량 계산, 복습 추천이 서로 영향을 주기 때문에 요구사항을 문서로 정리하고 실제 구현과 비교하면서 TODO를 수정하는 과정이 필요했다. UI도 한 번에 완성되지 않았고, 작은 화면과 긴 글자 등 여러 상황을 확인하면서 개선했다. AI를 사용하더라도 결과를 검증하고 최종 기준을 결정하는 역할은 개발자에게 남아 있음을 느꼈다.

### 결론

차곡차곡 1.0의 핵심인 **간편한 학습 기록**을 유지하면서, 2.0에서는 **시험·학습 계획·복습·통계**가 연결되는 학습 관리 앱으로 발전시켰다. 소스와 기존 개발 기록에는 핵심 기능 구현 및 자동·Chrome 검증 흔적이 있으나, 실제 사용자 1.0 데이터 전환과 일부 최종 배포·실기기 검증은 별도 확인이 필요하다.
