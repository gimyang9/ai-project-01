# 차곡차곡 2.0

학습 자료의 진도와 시험 목표를 관리하고 이해도 기반 복습을 돕기 위한 개인 학습 관리 웹앱입니다. 대학생과 여러 시험을 병행하는 학습자를 대상으로 합니다.

> 2026-10-25 최신 상태: **3단계 시험 관리·권장량·예상 완료일 구현**을 마쳤습니다. 자료별 기록 기간에 따른 최근 7/14/28일 평균과 시험 당일 제외 권장량을 분리해 안내합니다. 자동 테스트 90개 통과. 실제 브라우저·사용자 1.0 백업 복사본 검증은 대기입니다. 스마트 복습·실제 통계·PWA는 후속 단계입니다. [3단계 검증 기록](docs/stage3-validation.md)을 확인하세요.

## 1. 제작한 것 소개

홈·시험·통계·더보기의 네 화면, 학습 자료 카드와 상세 화면, 진도·복습 입력 모달을 제공합니다. 자료·기록·메모·시험·중단/보관 상태를 2.0 통합 저장소에 저장합니다. 1.0 원본과 이전 시험 저장 키는 보존합니다. 설정에서 1.0/2.0 백업을 복원하고 통합 백업을 내려받을 수 있습니다. 통계·캘린더만 예시입니다.

기존 1.0 소스는 [reference/v1](reference/v1)에 보존돼 있습니다. 2.0에는 숲과 식물 중심 디자인, 시험과 자료의 연결, 시험 중단 시 자료별 계속 학습 선택 UI가 추가됐습니다. 이는 실제 1.0 데이터 연동 완료와 구분합니다.

### 기술과 실행

- HTML, CSS, 일반 JavaScript. 프레임워크와 빌드 단계 없이 `dist`의 정적 파일을 제공합니다.
- 주요 코드: [app.js](dist/app.js), [시험 관리 모듈](dist/exam-management.js), [연속 학습 계산](dist/streak.js), [권장량·적응형 평균 예상일](dist/learning-plan.js).
- 이미지·폰트는 로컬 에셋이며 출처는 [ASSETS.md](ASSETS.md), [폰트 출처와 라이선스](dist/assets/fonts/licenses/SOURCES.md)를 확인합니다.
- 통합 저장 키: `chagok-v2-data-v1`. 자료·기록·시험·수동 계획을 함께 저장합니다. 기존 1.0과 시험 미리보기 키는 읽기만 하여 보존합니다.

Python이 설치된 환경에서는 프로젝트 루트에서 다음 명령으로 실행할 수 있습니다. 이 명령의 이번 환경 실행 및 브라우저 검증은 아직 하지 않았습니다.

```powershell
python -m http.server 8000 --directory dist
```

브라우저에서 `http://localhost:8000`을 엽니다. 같은 주소·포트·브라우저를 사용해야 동일한 LocalStorage에 접근합니다. `dist/index.html`을 직접 여는 방식은 HTTP 실행 검증을 대체하지 않습니다.

## 4. 사용한 스킬

기존 기록에는 프로젝트 전용 커스텀 스킬 **chagok-data-guard**의 실제 적용 사례 CG-SKILL-001~012가 남아 있습니다. 선택 목적은 기존 자료·원본 이력·수동 설정 보존과 저장 경계 검증입니다. [적용 기록](docs/skill-usage-log.md), [구조화 기록](docs/skill-usage-log.jsonl), [검증 근거](docs/evidence)를 참고합니다.

최초 제출 문서 정리 때는 원문을 찾지 못해 스킬을 사용하지 않았습니다. 이후 사용자 요청으로 **프로젝트용 커스텀 버전을 새로 작성**했습니다. [SKILL.md 전문](skills/chagok-data-guard/SKILL.md), [후보 비교·선택 이유·사용법](docs/skill-selection.md), [검증 보조 도구](skills/chagok-data-guard/scripts/inspect-boundary.ps1)를 제공합니다. 과거 원문 복원본이 아닙니다.

작성 후 실제로 읽고 현재 저장 경계·완료 표현 검토에 적용했습니다(CG-SKILL-013). 예시 학습 기록과 시험 저장을 구분하고 소스 해시·저장 접근 후보를 수집했습니다. 소스 검토 범위의 결과이며 런타임 무손실 검증은 남아 있습니다. 이후 작업은 AGENTS.md의 경로 지시에 따라 스킬을 읽고 적용 결과를 두 로그에 남깁니다. 전역 설치는 하지 않았습니다. 작성 자체·실제 적용·과거 기록을 구분하며 생성 이전 구현을 소급 사용으로 기록하지 않습니다.

## 5. 검증과 제출 상태

기존 테스트는 Node.js의 내장 테스트 러너를 사용합니다.

```powershell
node --test tests/streak.test.cjs tests/exam-management.test.cjs tests/study-data.test.cjs tests/study-app.test.cjs tests/learning-plan.test.cjs
```

PATH의 node는 없지만 Codex 런타임의 node.exe를 찾아 90개 테스트를 실행해 모두 통과했습니다. 실제 실행 경로와 결과는 3단계 검증 기록과 docs/evidence/stage3-plan-tests.tap에 있습니다. 브라우저 연결이 없어 화면·파일 선택/다운로드·실기기 검증은 미실시입니다.

[제출 점검표](docs/submission-checklist.md)에 완료·미완료·확인 필요를 구분했습니다. 현재 폴더에는 `.git`이 없어 기존 커밋 이력과 원격 저장소, Public 여부를 확인할 수 없고 커밋·Push도 수행하지 않았습니다. 기존 Git 저장소를 먼저 확보해 이력을 유지해야 합니다.

## 6. 느낀 점 및 결론 초안

아래는 확인된 개발 기록을 토대로 한 초안이며, 제출자가 자신의 경험에 맞게 수정해야 합니다.

예시 화면이 동작하는 것과 실제 기록을 저장·복원하는 것은 다른 완료 기준이라는 점이 드러났다. 시험 중단과 자료 직접 중단을 구분하고 수동 설정과 원본 이력을 보존하는 규칙을 명확히 하는 과정이 필요했다. AI를 통한 반복적인 화면 개선과 문서 정리는 도움이 되지만, 실행 근거 없이 완료를 판단하면 구현 상태와 보고가 어긋날 수 있다.

앞으로 기존 데이터의 안전한 전환과 백업 왕복 검증을 우선하고, 실제 기록 기반 추천·통계·PWA를 순서대로 연결한다. 현재 결과물은 디자인과 시험 관리 흐름을 확인할 수 있는 중간 단계다.

**제출자 작성 필요:** 직접 체감한 장단점, 가장 어려웠던 문제, AI 제안 중 채택·수정한 사례, 최종 소감.
