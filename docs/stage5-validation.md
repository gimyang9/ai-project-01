# 5단계 — 실제 통계·캘린더·식물 성장·PWA 검증

2026-10-26. 5-1~5-11 구현과 합성 검증 완료. 5-12의 PWA 구현·Chrome 로컬 검증은 완료했으며 실제 iPhone Safari·홈 화면 설치 실행 확인은 남아 있다. 전체 자동 테스트153개 통과. 6단계는 아직 진행하지 않았다.

## 통계와 캘린더

study-stats.js는 원본을 변경하지 않는 집계 모듈이다.
- 현재 월요일부터 오늘까지 주간, 이번 달1일부터 오늘까지 월간, 현재 달을 포함한 최근3개/6개 달의 시작일부터 오늘까지 집계한다. 화면에 정확한 날짜 범위를 표시한다.
- 과거 회독과 보관 자료를 포함해 실제 이력을 읽는다. 미래 기록과 학습량0인 위치 기록은 완료 학습 건수·공부한 날로 만들지 않는다.
- 학습/복습 기록 건수와 기록한 날짜 수를 집계한다. 실제 반복 복습 기록은 각각 한 건으로 세며 추천용 합집합 속도 계산과 역할을 구분한다.
- 페이지·강·단어 등 다른 단위를 합산하지 않는다. 주간 분량은 단위별로 따로 표시한다.
- 학습 비중은 학습 기록 건수 기준이다. 여러 시험에 연결된 기록은 각 시험에1/N씩 나누며 총 분모를 늘리지 않는다. 연결되지 않은 자료는 독립 학습, 자료별 선택은 각 자료 이름으로 집계한다.
- 연결 관계와 이름은 현재 상태 기준이다. 기록 당시의 시험 연결 스냅샷을 저장한 것처럼 표시하지 않는다.
- 실제 기간별 막대 추이와 빈 데이터0 상태를 표시한다.0건 막대에 최소 높이로 가짜 실적을 만들지 않는다.
- 주간 요약과 기존 학습 속도·예상 완료일 모듈을 연결한다. 기존 추천 계산식은 바꾸지 않았다.
- 캘린더 채움은 완료 기록, 테두리 점은 현재 복습 예정, 마름모는 집중 복습 시작이다. 날짜 클릭 시 원본 이름·범위·회독·이해도와 현재 일정을 분리한다.
- 예정은 현재 계산 결과이며 과거 계획 이력을 복원한 것이 아니다. 자료·기록 수정/삭제/보관/복원 시 다시 집계한다.

## 식물 저장

자료의 선택형 growthState={family,completed}를 도입했다. 기존 저장 키와 데이터/백업 버전은 유지한다.
- 새 자료는 자료 ID에 따른 안정적인 자동 배정으로 꽃·나무·선인장·버섯 중 하나를 저장한다. 사용자 선택 UI는 추가하지 않는다.
- 기존 식물 별칭은 보존한다. 옛 자료는 읽기 시 강제로 저장하지 않고, 같은 ID의 안정적인 종류를 표시하며 해당 자료를 다음에 저장할 때 성장 상태를 함께 보존한다.
- 단계는0~10%,10%초과~30%,30%초과~60%,60%초과~100%미만,100%이다.
- 최초 완성 후에는 진도 수정/삭제나 다음 회독·보관/복원으로 완성 상태를 되돌리지 않는다. 현재 진도와 회독 계산은 그대로다.
- 기존 기록 ID·날짜·순서·이해도·단위·과거 회독·수동 복습 계획과 알 수 없는 필드를 보존한다.
- 실패한 저장은 기존 메모리·저장 원본을 바꾸지 않는다. 백업/복원은 식물 상태도 왕복 보존한다.

## PWA와 게시 준비

manifest.webmanifest, pwa.js, service-worker.js 및 기존 favicon 기반192/512px 아이콘과180px Apple 아이콘을 추가했다. 원래 아이콘과 일러스트는 보존했다.
- start_url과 scope, 아이콘·worker 등록 경로가 상대 경로여서 GitHub Pages 프로젝트 하위 경로를 지원한다.
-25개 정적 앱 자산을 버전별로 캐시한다. 개인 자료는 기존 LocalStorage에 유지하며 정적 캐시와 분리한다.
- 현재 scope의 자기 캐시만 정리한다. 다른 앱 캐시·기존 저장 키를 지우지 않는다.
- 업데이트 중 열린 기록 폼을 강제로 교체하지 않는다. 새 worker는 대기하며, 앱을 완전히 닫고 다시 열 때 새 버전이 적용된다.
- 매니페스트와 Chrome 설치 요건 진단은 오류0개였다. 이것은 실제 iPhone 설치 확인을 뜻하지 않는다.
- 파일 직접 열기는 일반 앱 실행만 가능하며 서비스 worker는 등록하지 않는다. PWA는 HTTPS 게시 또는 localhost에서 확인한다. 서비스 worker 수명주기·보안 환경은 [MDN 공식 문서](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers)를 참고했다.

앱 코드/스타일/자산 변경 후 게시 전에 다음을 실행해야 캐시 버전이 함께 갱신된다.

    node scripts/build-pwa.cjs

스크립트는 root와 dist 각각의 실제 파일 해시로 worker를 생성한다. 두 CSS에 남아 있는 기존 차이는 합치지 않고 각 게시 자산 버전에 반영한다. 최종 게시 대상은 기존대로 dist이며 이번 작업에서 커밋·배포하지 않았다.
