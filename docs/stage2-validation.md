# 2단계 구현 및 검증 — 2026-10-24

사용자의 “2단계 진행하자” 승인으로 2-1~2-14를 구현했다. 프로젝트의 chagok-data-guard 원문을 읽고 적용했다. 3단계 자동 권장량·4단계 복습 알고리즘·5단계 실제 통계/PWA는 이번 범위에 포함하지 않았다.

## 저장 구조와 전환

| 구분 | 키 / 형식 | 처리 |
|---|---|---|
| 1.0 원본 | `study-progress-data-v1`, version 1 | 읽기만 수행, 원본 문자열 보존 |
| 기존 시험 미리보기 | `chagok-v2-preview-exams-v1`, version 1/2 | 읽기와 메모리 변환만 수행, 원본 문자열 보존 |
| 2.0 현재 데이터 | `chagok-v2-data-v1`, app `chagok-v2`, version 1 | study와 exams를 한 JSON으로 함께 저장 |
| 오류 후 명시적 복원/초기화 | `chagok-v2-data-v1.before-recovery.N` | 읽지 못한 v2·1.0·시험 원문을 별도 보존한 후 현재 키 교체 |

같은 출처(origin)의 저장값만 자동으로 가져올 수 있다. 다른 호스팅 주소·브라우저의 1.0 데이터는 기존 앱에서 백업 파일을 내려받아 2.0 설정에서 복원해야 한다. 사용자 브라우저의 실제 저장값은 이번 작업에서 읽거나 변경하지 않았다.

신규 설치는 예시 자료 없이 시작한다. 2.0 키가 있으면 1.0을 다시 가져오지 않는다. 1.0 데이터와 기존 시험을 모두 검증한 다음 새 키에 쓰고, 쓰기가 실패하면 변경을 중단한다. 알 수 없는 버전·잘못된 JSON은 자동 교체하지 않는다. 오류 안내는 화면에 유지한다. 검증된 백업의 명시적 복원 또는 초기화 시에만 오류 원문을 별도 키에 보존한 후 재개한다. 보존 저장이 실패해도 교체하지 않는다.

1.0의 자료 ID, 기록 ID·날짜·순서, 회독·부분 복습·메모와 알 수 없는 필드를 유지한다. 진도 표시와 학습량은 날짜·sequence 순서로 계산한다. 같은 날짜의 새 기록은 기존 최대 순서 뒤에 추가한다. 이해도 선택은 원본 기록에 저장하되 추천 간격은 계산하지 않는다. 1.0에 없던 시각을 과거 사실로 만들어 채우지 않는다. 새 기록에는 생성 시각을 저장한다.

기록이 있는 자료의 단위 변경을 거부하여 기존 숫자 범위의 의미를 보존한다. 전체 분량 변경은 현재 회독 기록이 범위를 벗어나면 거부한다. 부분 복습은 당시 total/unit을 보관하므로 자료 전체 분량을 바꿔도 과거 복습 범위는 변환하지 않는다. 다음 회독은 완료된 현재 회독을 통째로 roundHistory에 보존한다. 보관 해제는 보관 전 직접 중단 상태를 유지한다.

## 구현 연결

- 2-1~2-2: 원본 구조 조사, 전환·검증 모듈과 원본 보존 경로.
- 2-3~2-4: 자료 등록·수정·삭제, 5종 유형·사용자 지정 단위·분량 저장.
- 2-5~2-7: 날짜·현재 위치·선택 이해도 기록, 수정/삭제 확인과 학습량·현재 진도 재계산.
- 2-8~2-9: 전체 완료 후 다음 회독, 과거 회독 조회, 부분 복습 추가·수정·삭제.
- 2-10~2-13: 자료 ID별 메모·목표 완료일, 직접 중단, 이력 보존 보관/복원과 실제 개수 배지.
- 2-14: 자료·기록·메모·시험·상태 통합 백업, 검증 후 복원 확인, 전체 2.0 초기화 확인.

1.0의 두 백업 형식(backupVersion 1 envelope 및 exportedAt가 있는 이전 flat 형식)을 받는다. 1.0 백업에는 시험이 없으므로 정상 로드된 현재 시험은 유지한다고 복원 확인창에 명시한다. 초기 로드 오류 상황에서 1.0 백업으로 복원하면 시험 목록이 비어 있음을 별도 안내한다. 2.0 백업은 시험까지 함께 교체한다. 초기화는 현재 2.0 데이터만 비우고 보존된 1.0과 이전 시험 원본은 삭제하지 않는다.

## 실행 근거

Node는 PATH에 없지만 다음 실행 파일을 확인했다.

```powershell
& 'C:/Users/alsru/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node.exe' --test tests/streak.test.cjs tests/exam-management.test.cjs tests/study-data.test.cjs tests/study-app.test.cjs
```

결과는 `docs/evidence/stage2-tests.tap`에 기록한다. 데이터/저장 테스트 16개, 앱 모의 DOM 연결 테스트 5개, 기존 시험/연속일 테스트 35개, 총 56개를 실행한다. 입력 폼 저장 후 재로드, 보관 배지, 기록 표시, 저장 실패 시 현재 상태 유지와 오류 후 복구 경로를 검사한다. 테스트 저장소와 데이터는 모두 합성 값이다.

수정 전후 `inspect-boundary.ps1` 결과를 `stage2-boundary-before.json`, `stage2-boundary-after.json`에 저장했다. 기본 정책에서 스크립트가 거절되어 기존 작업과 같은 프로세스 한정 ExecutionPolicy 옵션으로 실행했다. 시스템 정책은 변경하지 않았다. reference/v1 보존 파일 6개의 해시는 전후 동일하다. 정적 검색은 간접 접근을 놓칠 수 있으므로 모듈 실행 테스트와 함께 판단했다.

## 한계와 남은 확인

- 연결 가능한 브라우저가 없다(`cua.getState()`의 apps/browsers 모두 빈 배열, iab unavailable). Playwright/DOM 패키지도 사용할 수 없다.
- 모의 DOM 검사는 실제 브라우저의 이벤트·파일 선택/다운로드·레이아웃 검증을 대체하지 않는다. 모바일/PC의 입력·모달·백업 파일 왕복을 실제 브라우저에서 재검증해야 한다.
- 실제 사용자 1.0 백업 복사본 전환, iPhone Safari·설치형 PWA는 미검증이다. 합성 데이터의 무손실 검사를 실제 데이터 전환 성공으로 표현하지 않는다.
- 통계·캘린더는 예시임을 유지한다. 홈은 실제 자료의 남은 분량을 표시하고 자동 권장량을 만들어내지 않는다. 복습 자동 추천은 준비 중으로 표시한다.
- 구현은 완료했으나 2단계 최종 화면 확인과 사용자 확인은 대기다. 3단계는 시작하지 않았다. 커밋·Push·배포는 하지 않았다.
