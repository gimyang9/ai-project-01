# TODO 변경 이력

## 기록 원칙

기존 PRD·후속 결정·상세 TODO를 보존한다. 과거 변경은 저장된 문서가 확인하는 범위만 요약하며, 이번 작업에서 수행한 것으로 표시하지 않는다. 날짜와 커밋은 확인할 수 있을 때만 기록한다.

## 이번 정리 이전에 문서로 확인되는 변경

| 변경 전 계획 | 변경 후 계획 | 이유·근거 | 적용과 검증의 범위 |
|---|---|---|---|
| 목표 중요도 선택 | 단일 우선 시험 지정 | PRD-updates.md의 시험 관리 후속 결정 | 시험 미리보기 코드 존재. 이번 재실행 미검증 |
| 자료별 학습 유지 사전 설정 | 시험 중단/마무리 때 자료별 선택, 매번 미선택 기본값 | PRD-updates.md, CG-SKILL-008 | 미리보기 상태와 모달에 적용된 코드 존재. 실제 1.0 연동 미완료 |
| 초기 복습 수치 제안 | 실제 기록 기반 추천, 초기 추정량·여유일은 사례 확인 후 결정 | PRD-updates.md의 집중 복습 결정 | 계획 변경이며 자동 추천 계산 구현 완료가 아님 |
| 화면 구성 중심 1단계 | 승인된 배너·폰트·모달·더보기 개선 | PROGRESS.md, CG-SKILL-002~012 | 과거 QA 근거 존재. 이번 브라우저 재검증 미실시 |

원래 TODO 문구 전체와 변경 시각을 확정할 Git 이력은 현재 폴더에 없다. 위 표는 문서 간 차이의 요약이며 당시 원문 TODO의 복제본이 아니다.

## SUB-001 — 2026-10-24 과제 제출 문서 정리

- 변경 전 계획: 기존 6단계 TODO를 유지하며 실제 데이터 연결과 최종 검증을 후속 단계로 둔다. 제출용 README와 별도 TODO 변경 이력은 없다.
- 변경 후 계획: 기존 앱 개발 단계에 앞서 제출 문서·상태 차이·누락 근거를 정리한다. 앱 개발 번호와 완료 체크는 유지한다.
- 이유: 최신 과제 지침이 개발 과정, 실제 스킬 활용, Git 이력 및 검증 가능한 제출 체크리스트를 요구한다.
- 실제 적용: README, 이 문서, 제출 점검표를 작성하고 TODO와 PROGRESS에 연결했다. 앱과 reference/v1은 수정하지 않았다.
- 검증 결과: 소스와 문서 대조로 예시 데이터와 시험 저장 범위를 확인했다. `git status`, `git log`는 Git 저장소가 아니어서 실패했다. 기존 자동 테스트 명령은 Node.js 부재로 실행하지 못했다. 브라우저 검증과 외부 Public 확인은 미실시다.
- 스킬: chagok-data-guard 원문을 확보하지 못해 이번 사용 기록을 추가하지 않았다.
- 커밋: 미수행. 기존 저장소 확보 후 이 문서 작업을 독립된 실제 커밋으로 남긴다. 과거 작업으로 소급하지 않는다.

## 후속 작업 순서

아래는 SUB-001 당시의 순서다. 후속 사용자 지시에 따라 커스텀 스킬은 새 버전으로 작성했고 Git 커밋은 사용자가 직접 수행한다.

1. 기존 Git 저장소 및 chagok-data-guard 원문·참조·검증 도구 확보.
2. 실행 환경을 준비하고 기존 테스트·브라우저 동작을 재검증한 뒤 실제 근거 기록.
3. 기존 Git 이력을 유지하며 제출 문서 변경부터 의미 있는 단위로 커밋.
4. 2단계 데이터 연결은 기존 단계 확인 절차에 따라 진행. 복습 수치 등의 미확정 규칙은 사례 확인 후 구현.
5. 실제 구현 범위에 맞춰 체크리스트 갱신, 공개 전 민감정보 점검, 원격 Push 및 Public 여부 확인.
