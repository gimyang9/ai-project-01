## 직접 확인할 기능

- **오른쪽 세로 손잡이 드래그:** 프레임 너비를 자유롭게 변경한다. 드래그 시작 시 수동 모드로 바뀐다.
- **브라우저 너비에 맞춤:** 이 옵션을 켜고 브라우저 창 자체를 늘리고 줄인다. 확대·축소 테스트에도 사용할 수 있다.
- **실제 CSS 너비 표시:** 프레임 너비와 별도로 배너의 실제 너비·높이를 소수점 단위로 표시한다.
- **기존/개선 전환:** 같은 프레임과 같은 이미지에서 스타일만 전환한다.
- **767·768px 등 프리셋:** 경계를 빠르게 비교한다. 숫자 입력도1px 단위로 가능하다.
- **손잡이 키보드 조작:** 좌우 방향키1px, Shift+방향키10px, Home320px, End1920px.
- **배경 빈 영역 상태:** 이미지 경계가 실제 배너를 덮는지 실시간으로 표시한다.
- **원본 크기 표시:** iframe 전체를 scale로 축소하지 않는다. 프레임이 브라우저보다 넓으면 검토 영역 내부의 가로 스크롤로 확인한다.

### 두 가지 보기

**배너 단독:** 프레임 너비가 배너 컨테이너 너비다. 카메라의 연속 변화와767/768px 경계를 직접 확인하기 좋다.

**실제 앱 배치:** 현재 앱의 사이드바·본문 최대 너비·여백과 배너 구조를 사용한다. 1024px에서는 기존 사이드바 전환으로 배너가 사용할 수 있는 폭이 달라진다. 따라서 프레임 너비와 배너 실제 너비가 다르다. 이 페이지가 해당 전환을 숨기거나 변경하지 않는다.

## 개선 방식

- 기존 배너 이미지와 로고를 그대로 사용한다. 배경색을 덧칠하거나 새로운 이미지를 만들지 않았다.
- 높이는 배너 자신의 폭에 비례하다가210px에서 멈춘다. 화면 너비별 높이 분기를 사용하지 않는다.
- 배경·로고·오두막은 **동일한 배너 컨테이너**를 기준으로 계산한다.
- 이미지 원본 비율은 유지하고 카메라 위치를 배너와 이미지 크기 차이에 따라 계산해 빈 영역을 방지한다.
- 일반 PC의 가장 좁은 본문 폭에서도 풍경·로고 크기가 유지되도록 스케일 상한에 도달하는 지점을 조정했다.
- 개선 CSS에는 화면 너비에 따른 미디어 쿼리나 이미지 교체가 없다. 767/768px에서 서로 다른 고정 로고 폭으로 전환하지 않는다.
- 드래그할 때 iframe을 다시 로드하거나 이미지 경로를 바꾸지 않는다.

## 실제 앱과의 동일성

frame.html의 home-intro 구조는 현재 dist/index.html에서 가져온 실제 배너·날짜·인사 카드 구조와 일치한다. 이미지 상대 경로만 미리보기 폴더 위치에 맞췄다. 앱의 **dist/style.css를 직접 불러온다.**

승인 전 개선안은 camera.css와 camera-continuous 클래스로 검토했다. 현재는 **실제 앱의 dist/banner-camera.css를 직접 불러오며 같은 클래스**를 사용한다. 배경 위치를 계산하는 별도의 미리보기 전용 JavaScript는 없다.

frame-shell.css는 배너 단독 보기의 외곽 여백을 정리하고 실제 앱 배치를 전환하는 검토용 코드다. review.js는 프레임 너비와 손잡이를 제어하고, frame.js는 스타일 전환과 측정값 보고만 한다. 앱 기능·저장 스크립트를 불러오지 않고 LocalStorage에 접근하지 않는다.

## 미리보기 단계 검증(실제 적용 전)

실제 Chrome headless 렌더링과 마우스 입력으로 다음을 확인했다.

- 320~1920px 주요 너비와767/768px·935/936/937px 등 경계.
- **실제 포인터 드래그620→800→620px를1px 단위로 왕복.**
- 이미지의 가로·세로 비율, 배너 덮임, 연속 드래그 중 배경/로고/오두막 위치·크기 변화.
- 기존 배너에서 빈 영역 재현, 같은 조건의 개선 배너에서 빈 영역 해소.
- 실제 앱 배치 보기, 브라우저 너비 연동, 실제 Chrome 창 크기 변경.
- Chrome 실제 페이지 확대80/90/100/110/125/150/200%.
- 손잡이 키보드 조작, 전체 프레임 축소 없음, 앱 저장 스크립트 미실행.

최종452개 측정(실제 포인터 드래그361개 포함)이 통과했다. 개선 배경의 최대 빈 영역은0px, 런타임 오류와 누락 에셋은0건이었다. 앱 배치의1023→1024px 전환에서도 배경1120px·로고265px 크기는 유지됐다. 실제 앱 파일162개의 해시가 변경 전과 같았다.
