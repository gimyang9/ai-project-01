# 차곡차곡 학습·복습 계산 검증

차곡차곡 앱의 학습 계획 및 복습 계산 결과를 고정된 기준일과 독립적으로 계산한 기대값을 사용해 검증합니다.

계산 정책 변경이나 오류 수정 후 기존 계산이 정상적으로 유지되는지 확인하는 것이 목적입니다.

단순 화면·문구 수정에는 전체 계산 검사를 강제하지 않습니다. 검증 과정에서 앱 코드와 기존 테스트 결과를 임의로 수정하지 않습니다.

## 1. 계산 정책 및 검사 범위 확인

검사 전에 다음 자료를 확인합니다.

1. **최신 계산 정책:** 사용자가 확정한 학습·복습 계산 규칙
2. **관련 문서:** `docs/PRD-updates.md`와 관련 보고서
3. **검사 대상:** root 또는 dist의 순수 계산 모듈
4. **기준일과 시간대:** 날짜 계산에 사용할 고정 기준
5. **합성 입력:** 학습량, 진도, 학습 기록, 시험일, 복습 범위 등
6. **검사 범위:** 변경된 계산과 영향을 받을 수 있는 기존 계산

최신 사용자 결정과 문서·테스트의 기대값이 충돌하면 임의로 정답을 선택하지 않습니다.

정책의 근거가 불명확한 항목은 미검증으로 기록하고 충돌 내용을 보고합니다.

실제 사용 이전의 개발에 이 스킬을 적용했다고 소급 기록하지 않습니다.

## 2. 독립적인 기대값 작성

검사에서는 다음 두 가지를 구분합니다.

- **원본 불변성:** 검증으로 기존 데이터와 상태가 변경되지 않았는가?
- **계산 정확성:** 계산 결과가 정책에 따른 정답과 일치하는가?

구현 함수를 다시 호출한 결과를 기대값으로 사용하지 않습니다.

작은 달력의 날짜 열거, 정수 위치 집합, 독립적으로 작성한 계산식 등 검사 대상 구현과 다른 방식으로 기대값을 구합니다.

기존 테스트가 실패해도 테스트를 삭제하거나 기대값을 임의로 변경해 통과시키지 않습니다.

## 3. 검사 실행

`scripts/check-learning.cjs`를 사용해 root 또는 dist의 순수 계산 모듈을 메모리에서 실행합니다.

브라우저, 사용자 저장소, 앱 파일은 변경하지 않으며 결과는 새로운 파일로만 저장합니다.

```powershell
node skills/chagok-learning-check/scripts/check-learning.cjs --root . --source root --today <기준일:YYYY-MM-DD> --out <새결과.json>
```

배포 사본도 검사 대상이면 `--source dist`로 별도 실행합니다.

실행 규칙:

- `--today`에 고정 기준일을 반드시 지정합니다.
- 운영체제의 시계는 변경하지 않습니다.
- Node.js가 PATH에 없으면 확인된 실행 파일 경로를 사용합니다.
- 실행 명령, 대상 경로, 런타임 환경을 결과에 기록합니다.
- 기존 결과 파일을 덮어쓰지 않습니다.

### 정책 프로필 확인

내장 검사는 현재 회독 기준 정책과 계획·실제 예상 완료일 분리를 대상으로 합니다.

실행 결과의 `policyProfile`은 검사 정책의 식별자이며 스킬의 작성일을 의미하지 않습니다.

1/3/7일 복습 간격, 간격 배수, 현재 회독 기준 등 정책이 변경되었다면 다음 순서로 처리합니다.

1. 최신 사용자 결정과 관련 문서를 확인합니다.
2. 기존 검사 프로필과 새 정책의 차이를 정리합니다.
3. 과거 정책과 다르다는 이유만으로 앱을 실패 처리하지 않습니다.
4. 필요한 경우 이 스킬 폴더의 검사 사례만 수정합니다.
5. 정책 충돌이 해결되지 않은 검사는 미검증으로 남깁니다.

앱 소스나 기존 정책 문서를 검증 과정에서 자동 수정하지 않습니다.

## 4. 계산 검증 항목

변경 내용과 관련된 항목을 선택하여 검사합니다.

### 4.1 학습 계획 및 권장 학습량

- 자동 학습 계획과 수동 설정 계획
- 남은 분량에 따른 권장 학습량
- 오늘 학습한 분량과 남은 학습량
- 이미 반영한 학습량의 중복 계산 방지
- 학습 가능 요일과 쉬는 날
- 계획 변경 후 남은 분량의 재계산

### 4.2 예상 완료일

다음 두 계산을 독립적으로 확인합니다.

**계획상 예상 완료일**
- 설정된 학습 계획과 예정 학습량을 기준으로 계산
- 자동·수동 계획의 차이 반영
- 계획 변경에 따른 예상일 갱신

**실제 예상 완료일**
- 실제 학습 기록과 학습 속도를 기준으로 계산
- 현재 회독에 해당하는 기록 사용
- 기록이 부족할 때의 정책 적용
- 계획상 예상일과의 혼동 여부 확인

두 예상일은 각각의 계산 기준과 기대값을 별도로 기록합니다.

### 4.3 복습 일정과 범위

- 최초 학습 및 복습 후 다음 추천일
- 정책에 따른 복습 간격과 배수
- 이전 복습 간격과 이해도에 따른 계산
- 복습 범위의 중복과 겹침 처리
- 동일 범위에 대한 최신 기록 반영
- 복습 일정 변경 후 기존 이력 보존

현재 구현에서 연속 성공 횟수는 별도로 관리하며 복습 간격 계산에는 사용하지 않습니다.

겹치는 범위는 가능한 경우 작은 정수 위치 집합으로 변환해 독립적으로 검증합니다.

### 4.4 경계 및 예외 사례

변경과 관련된 기존 테스트를 선택해 다음 경계를 보완합니다.

- 학습 기록이 없거나 부족한 상태
- 계획 완료 또는 남은 분량이 없는 상태
- 날짜가 변경되는 경계
- 매우 큰 학습량이나 긴 기간
- 여러 시험과 연결된 학습 자료
- 미리보기 계산 후 원본 상태의 불변성

내장 사례만 실행하고 모든 계산 정책을 검증했다고 표현하지 않습니다.

## 5. 검사 결과 판정

| 판정 | 기준 |
|---|---|
| 통과 | 독립 기대값과 실제 계산 결과가 일치함 |
| 실패 | 기대값과 실제 결과가 다르거나 원본 상태 변화가 확인됨 |
| 미검증 | 실행 불가, API 부재, 정책 충돌, 지원하지 않는 프로필 등으로 판정할 수 없음 |

실행 준비 실패를 계산 오류로 단정하지 않습니다.

날짜 의존 오류가 발생하면 고정 기준일과 런타임 시계가 혼용되었는지 확인합니다.

필요한 경우 명시적인 고정 시계나 기존 원본과 비교하되, 검사 조건을 변경해 최초 실패 결과를 없애지 않습니다.

검사 실패 시 앱을 자동 수정하지 않고 재현 입력과 원인을 보고합니다.

## 6. 검증 결과 보고

결과에는 다음 내용을 포함합니다.

1. 검사 대상 소스와 파일 해시
2. 적용한 계산 정책 및 근거
3. 기준일과 시간대
4. 실행 명령과 런타임 환경
5. 검사에 사용한 합성 입력
6. 독립적으로 계산한 기대값
7. 실제 함수 실행 결과
8. 항목별 통과·실패·미검증
9. 원본 상태 및 데이터 불변성
10. 추가로 검증하지 못한 조건

검증 결과는 실행한 사례와 확인한 정책 범위에 한정합니다.

실제 사용자별 최적 학습량이나 최적 복습일을 보장한다고 표현하지 않습니다.

## 7. 다른 스킬과의 역할 구분

- `chagok-learning-check`: 학습량, 예상 완료일, 복습 일정 및 범위 계산의 정확성
- `chagok-ui-regression`: 화면 배치, 모달, 입력·저장·취소·미리보기 조작
- `chagok-data-guard`: 데이터 보호와 프로젝트 적용 이력 관리

검증 실행 내역은 `chagok-data-guard`의 기존 활용 로그에 새로운 ID로 기록합니다.

스킬 작성·수정·구문 검사와 실제 앱을 대상으로 수행한 계산 검증은 명확히 구분합니다.

## 예외 상황

- **정책 충돌:** 최신 사용자 결정과 문서의 기준이 다르면 충돌을 기록하고 미검증 처리합니다.
- **실행 환경 오류:** Node.js 실행 불가 등으로 검사를 수행하지 못하면 미검증 처리합니다.
- **API 부재:** 필요한 계산 함수가 없거나 접근할 수 없으면 미검증 처리합니다.
- **지원하지 않는 정책 프로필:** 기존 기대값으로 실패 판정하지 않고 정책 변경 여부를 확인합니다.
- **계산 결과 불일치:** 기대값과 실제값을 함께 기록하고 실패 처리합니다.
- **원본 상태 변경:** 검사 중 데이터 변경이 확인되면 실패로 기록합니다.
- **날짜 의존 오류:** 기준일, 시간대, 런타임 시계를 구분해 재현 조건을 보고합니다.
